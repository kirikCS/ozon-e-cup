# Ozon E-CUP · Прогноз 30-дневного GMV — состояние решения

**Задача.** Предсказать суммарный GMV каждого из 250 000 клиентов за период
`2026-02-14 … 2026-03-15` по истории `2025-01-01 … 2026-02-13`.
**Метрика.** RMSLE с `log1p` по всем предсказаниям.

## 3. Теория: что именно оптимизирует RMSLE

Два результата, определившие всю дальнейшую работу.

### 3.1 Оптимальный прогноз

RMSLE — это MSE в шкале `log1p`, поэтому минимум достигается **условным средним
в лог-шкале**:

```
ŷ*(x) = expm1( E[ log1p(y) | x ] )
```

Лоссы, оптимизирующие `E[y|x]` (Tweedie, Poisson, Gamma), дают систематически завышенный
прогноз. Поправка Дуана (smearing), стандартная при лог-регрессии, здесь **вредна** —
она возвращает к условному среднему, то есть уводит от оптимума.

**Подтверждено численно:** LightGBM Tweedie в сыром виде — 2,4401, Poisson — 2,4786
(хуже наивного бейзлайна). Те же модели после лог-калибровки — 1,869 и 1,884.
Прямой L2 по `log1p` — 1,691.

### 3.2 Точная двухстадийная декомпозиция

Поскольку `log1p(0) = 0`:

```
E[log1p(y) | x] = P(y > 0 | x) · E[ log1p(y) | y > 0, x ]
```

Это **тождество**, а не приближение: классификатор и регрессор перемножаются без
поправочных коэффициентов, в отличие от обычной hurdle-модели в исходной шкале.

## 7. Калибровочный аппарат

После первых трёх сабмитов вся дальнейшая работа велась аналитически, поверх уже
имеющихся предсказаний.

### 7.1 Уровень

Для семейства `p_c = expm1(log1p(p) + c)` метрика — **точная парабола**:

```
RMSLE²(c) = R0² − 2·c·D + c²,   D = E[log1p(y)] − E[log1p(p)]
```

Три точки (`c = 0; 0,105; 0,190`) дали коэффициент при `c²` равным **1,000000** и две
независимые оценки `D`, совпавшие до шестого знака (0,10117 и 0,10117).

**Результат:** `E[log1p(y)]` на публичной выборке = **2,3284**. Сезонный сдвиг
относительно валидации — **+0,0863**. Оценка по календарному аналогу 2025 года давала
+0,176, то есть была завышена вдвое: в неё подмешался фиктивный рост от критерия отбора.

Проверка аппарата: `sub2`, `sub4`, `sub5` — один вектор при трёх сдвигах; после
приведения к общему уровню их `R*` должны совпасть. Совпали:
**1,6546852 / 1,6546822 / 1,6546798**, разброс 5·10⁻⁶.

### 7.2 Наклон

Для `p = expm1(b·log1p(p) + c)` при выровненном уровне:

```
R²(b) = Var(L) − 2b·Cov(L,P) + b²·Var(P)
```

Одна дополнительная точка (`b = 0,85`) разрешает систему:
**`b* = 1,0420`**, **`Cov = 2,53398`**, **`Var(L) = 5,366802`**.

`Var(L)` — величина глобальная, не привязанная к модели. Из неё немедленно
восстанавливается `Cov(L, Pᵢ)` для любого отправленного вектора, а значит и корреляция
каждой модели с таргетом.

### 7.3 Бленды и стеки

При выровненном уровне `Var(L)` сокращается, и скор бленда предсказывается **заранее**:

```
R²(w) = w·R*²₄ + (1−w)·R*²₈ − w(1−w)·Var(P₄ − P₈)
```

Обобщение на N векторов: `R²(w) = Σwᵢ·R*ᵢ² − ½ΣΣwᵢwⱼ·Var(Pᵢ − Pⱼ)`, а при известной
`Var(L)` — безусловная OLS-проекция `L` на линейную оболочку предсказаний.

**Точность предсказаний:**

| Сабмит | Предсказано | Факт | Ошибка |
|---|---|---|---|
| `sub11` (бленд 2) | 1,6524709 | 1,6524999 | 2,9·10⁻⁵ |
| `ols_stack` (стек 4) | 1,650791 | 1,6508950 | 1,0·10⁻⁴ |
| `stack6` (стек 6) | 1,649598 | 1,6496638 | 6,6·10⁻⁵ |

Единственный источник ошибки — ковариации считаются по всем 250 000, а лидерборд по
50 000 публичных. Устойчивость решений проверялась симуляцией на 60–80 случайных
подвыборках по 50 000.


## 9а. Прореживание признаков

Всё меряется на отдельном отборочном якоре `2025-12-15` (обучение на
`[318, 290, 262, 234, 206]`); VAL и HON в отборе не участвуют.

### Однократное отсечение по gain — ноль

`code/feat_select.py`: отранжировать один раз, выбросить хвост. Лучшая точка — 155
признаков, 1,74214 против 1,74216 у полного набора, то есть −0,00002. Ни один признак не
имеет нулевого gain.

**Этот результат ничего не доказывает.** Однократный gain — слабый критерий на
коррелированных входах: `gmv_30`, `gmv_60`, `gmv_90`, шесть блочных лагов и производные
описывают почти одно и то же, дерево делит выигрыш между дубликатами, и все члены группы
выглядят посредственно. Ранжирование врёт, отсечение режет наугад внутри групп.

### RFE — переобучение на каждом шаге

`code/rfe.py`, удаление 12% с переранжированием:

| Оставлено | RMSLE | к базе | corr с полной моделью |
|---|---|---|---|
| 165 | 1,74216 | — | 1,00000 |
| 128 | **1,74174** | −0,00042 | 0,99607 |
| 99 | 1,74216 | +0,00000 | 0,99595 |
| 53 | 1,74240 | +0,00024 | 0,99549 |
| 36 | 1,74302 | +0,00086 | 0,99480 |
| 30 | 1,74419 | +0,00203 | 0,99433 |

Два вывода.

**Одиночного выигрыша нет:** −0,00042 на грани шума. Но от 165 до 99 признаков качество
не меняется вообще, а до 53 падает на 0,0002 — весь аппарат из 165 колонок эквивалентен
примерно тридцати, остальное декорация.

**Прореживание почти не декоррелирует:** corr с полной моделью держится 0,994–0,996 даже
после выброса 80% колонок. При этом 0,9943 попадает в тот же диапазон, где живут компоненты
стека (0,992–0,999), а они друг другу помогают — стек выигрывает у лучшей одиночной модели
0,0037. Поэтому вопрос решался не корреляцией, а прямым замером бленда.

### Бленд по подмножествам: выигрыш есть, но не от подмножеств

`code/rfe_blend.py`: бленд семи стадий (165/128/99/77/53/36/30) даёт 1,73890 против 1,74379
у полной модели, **+0,0049**. Веса распределились почти равномерно, попарные корреляции
между стадиями 0,9941–0,9960.

Контроль `code/rfe_blend_control.py` — три ветки по семь моделей, бленд одинаковый:

| Ветка | Лучшая одиночная | Бленд | Выигрыш | Средняя попарная corr |
|---|---|---|---|---|
| A — 7 сидов, одинаковые 165 признаков | 1,74385 | 1,73860 | +0,00526 | 0,99598 |
| B — 7 подмножеств RFE, сид фиксирован | 1,74349 | 1,73862 | +0,00486 | 0,99533 |
| C — 7 подмножеств RFE + разные сиды | 1,74403 | 1,73877 | +0,00526 | 0,99521 |

Все три сходятся в одну точку. **Разнообразие подмножеств признаков не даёт ничего** —
семь сидов на одном и том же полном наборе работают не хуже. RFE как источник декорреляции
закрыт; гипотеза «обучать компоненты стека на разных наборах признаков» опровергнута.

Остаётся вопрос, чем является сам +0,005 — усреднением дисперсии или подгонкой наклона.
NNLS по семи столбцам с корреляцией 0,996 почти эквивалентен подбору одного скаляра на
`log1p(p)`, то есть калибровке наклона, а она в этой задаче стоит дорого сама по себе.
Разбор — `code/blend_confound.py`.

## 10. Что осталось нетронутым

Дальнейший прирост требует **новых признаков**, а не новых моделей — перебор архитектур,
как показано выше, потолок не сдвигает. По EDA неиспользованными остались:

1. **Внутринедельные паттерны** — эффект дня недели измерен на агрегате (разброс ±3%),
   но на уровне клиента как признак не заведён
2. **Структура интервалов между покупками** — используется только среднее; распределение,
   дисперсия и тренд интервалов не извлекались
3. **Разделение Поиск/Каталог на уровне последовательности** — сейчас только доли GMV
4. **Воронка на уровне клиента** — конверсии `поиск → корзина → заказ` считались
   агрегированно, персональные конверсии не заводились

Отдельный риск: калибровка настраивалась по 50 000 публичных клиентов, а private
считается по 200 000. Выжимание третьего знака дальше несёт риск переобучения под public;
сама модель (компоненты) от этого не страдает, страдает только калибровочная надстройка.

## 12. Известные дефекты

**Две невалидные ячейки в колонке `honest`.** В `t01` определено
`wG = lambda a, b: csG[:, b+1] - csG[:, a]` без защиты от отрицательных индексов
(в `t02b` защита есть — `max(..., 0)`). На honest-якоре 288 сезонный наив запрашивает
окно `a+1-365 = -76 … -47`; numpy заворачивает индексы, и вместо «года назад» берётся
сумма за дни 334–363, то есть `2025-12-05 … 2026-01-03` — **будущее относительно якоря**.
Затронуты `seasonal naive` (2,30197) и `0.5*prev30 + 0.5*seasonal naive` (2,11801).
У `prev365/12.17` ту же проблему поймали и занулили в `finalize.py`, эти две пропустили.
На колонку `val` и на итоговое решение не влияет.

**Изотоника учится не на том распределении.** В `t07_submit.py` веса NNLS и изотоническая
кривая подбираются на PROBE-предсказаниях (обучены до якоря 348), а применяются к FINAL
(обучены **включая** якорь 378). Изотоника — поточечное преобразование шкалы, а шкалы
выходов у этих двух наборов моделей разные. Это независимая от сезонности причина провала
`sub3` на лидерборде.

**`tgt_month` / `tgt_doy_sin/cos` работают как ID якоря.** Признаки константны внутри
якоря. У FINAL-набора месяцы целевых окон = {1, 1, 12, 11, 10}, на предсказании — 2,
то есть значение вне обучающего диапазона: дерево уходит в крайний лист. Частично
компенсируется тем, что уровень всё равно выставляется вручную в 2,3284.
