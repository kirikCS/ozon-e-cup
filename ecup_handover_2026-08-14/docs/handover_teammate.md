# Передача: как собран лучший саб и как продолжать · для сокомандника

Дата: 2026-08-13. Лучший измеренный вектор команды: **1,6478431526** (`submissions/twink_aggressive_lb1647843.csv`,
замерен твинком). Официальный топ-1 основного аккаунта: 1,6480488273 (`stack_dl_fusion`).
Очередной кандидат: `submission/queue/stack10_evgru.csv`, предсказание 1,647724 ± ~2·10⁻⁵.

## 1. Главная идея: стек как точная задача наименьших квадратов на лидерборде

Всё строится на трёх фактах, измеренных зондами (см. `text.md` §7):

- `E[log1p(y)]` на публичной выборке = **2,3284** (из трёхточечной параболы сдвигов);
- `Var(log1p(y))` = **5,366802** (из зонда наклона; переподтверждён 2026-08-13 зондом
  slope09 с точностью 1,2·10⁻⁵);
- для любого вектора P с измеренным лидербордным RMSLE R*:
  **Cov(L, P) = (Var_L + Var(P) − R*²) / 2** — точно, не оценка.

Отсюда: имея N измеренных векторов, оптимальная линейная смесь в log1p-шкале — обычный
ридж-OLS, и её лидербордный скор **предсказывается заранее**:
`R²(w) = Var_L − 2·wᵀk + wᵀCw`, где k_i = Cov(L, P_i), C — эмпирическая ковариация
уровне-выровненных векторов (по всем 250k; единственный источник ошибки — публичные 50k).
Исторические ошибки предсказаний тихих решений: 2,9·10⁻⁵ … 1,8·10⁻⁴; последние три — ≤2·10⁻⁵.

## 2. Аппарат: файлы и запуск

- **`code/t21_stack_corrected.py`** — решатель. Внутри: список V (векторы + их измеренные
  R*), реестр ограничений, min-norm коррекция k, ридж-свип с политикой весов, полоса
  честности, гейт «не хуже достигнутого». Запуск: `python code/t21_stack_corrected.py`.
  Режим `FX_TWINK=1` дополнительно пишет агрессивное решение (без лимита max|w|).
- **`model_out/stack_constraints.json`** — реестр измеренных смесей: каждый отправленный
  и замеренный стек добавляется сюда (`{"csv": ..., "lb": ...}`) и становится линейным
  ограничением на ошибку k. Сейчас 5 ограничений, все сходятся с точностью ≤4·10⁻⁵.
- Уровень: каждый вектор перед решением выравнивается `q − mean(q) + 2,3284`. Это
  идемпотентно; сырой уровень стоит на LB ровно `c²` в R² (см. инцидент §5.3).
- Все csv сортируются по user_id; порядок sample_submit = отсортированный.

## 4. Как добавить твой новый вектор (например, сырую нейронку)

1. Положи csv (250k строк, любой порядок, любой уровень).
2. Отправь его на LB (любой аккаунт), получи точный R*.
3. Добавь строку в V внутри t21: `("имя", "путь", R*)`.
4. `python code/t21_stack_corrected.py` — смотри веса/предсказание. Если новый вектор
   получает вес ≥0,1 — он несёт некоррелированную ошибку, кандидат улучшится.
Чем сырее (несблендованнее) вектор — тем ниже его корреляция с базисом и тем он ценнее:
сблендованные версии почти коллинеарны существующим (bwn↔stack_dl corr 0,9998).

## 5. Три урока, оплаченных сабмитами — не повторять

1. **Лонг-шорты на парах corr ≥ 0,998 запрещены.** stack8x (веса +0,50/−0,51 на паре
   two_stage-версий) промахнулся на +0,0016 при исторической точности 10⁻⁴. Политика
   решателя: max|w| ≤ 0,6, шорты ≤ 0,25 (агрессивнее — только после твинк-замера).
2. **Кросс-пайплайновые оценки R* не переносятся** (~±0,003): вектор, пересобранный в
   другом окружении, — другой вектор. Только собственный LB-замер делает алгебру точной.
   Внутрипайплайновая досидка сидов — переносится (шум ⊥ таргету).
3. **Уровень — часть пары (вектор, скор).** ts_9seed ушёл на LB с сырым уровнем
   (mean log1p 2,2276), а в базисе лежала выровненная версия — k получил сдвиг −0,005 и
   это исказило три решения подряд, пока ревью не вскрыло корень. Проверяй mean log1p
   файла, который реально ушёл: должен быть 2,3284.

## 6. Воспроизводимость с нуля

```bash
python code/server_prep.py     # панели из train.parquet (7 базовых)
python code/fx_panels.py       # 4 канальные панели воронки
python code/verify_setup.py    # 16 контрольных чисел
python code/verify_model.py    # эталон: ровно 1,69101 / 1,75150
python code/t21_stack_corrected.py   # решение из измеренных векторов
```
Компоненты: `code/t12_*` (two_stage 9 сидов), `t17_*` (two_stage v3), `t19_*` (catboost
v3), `t23_*` (seq_pure), `t24/t25_*` (evgru2). BTYD-параметры персистятся
(`model_out/btyd_params.json`, фиты с `key=` детерминированы). GPU-скрипты завершаются
`os._exit(0)` — «exit code 9» в фоне это шум CUDA-teardown, смотри последнюю строку лога.
